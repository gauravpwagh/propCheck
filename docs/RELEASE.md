# Release builds

## Before every release
```bash
flutter pub get
dart run build_runner build --delete-conflicting-outputs
flutter analyze
flutter test
```
Bump `version:` in `pubspec.yaml` (`1.0.0+1` → name `1.0.0`, build number `1`). The build number must go up on every upload.

## Android (AAB for Google Play)
1. Create an upload key once and keep it safe (never commit it):
   ```bash
   keytool -genkey -v -keystore ~/propcheck-upload.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload
   ```
2. Create `android/key.properties` (ignored by git):
   ```properties
   storePassword=...
   keyPassword=...
   keyAlias=upload
   storeFile=/absolute/path/to/propcheck-upload.jks
   ```
   Without this file, release builds are signed with the debug key (fine for local testing, rejected by Play).
3. Build:
   ```bash
   flutter build appbundle --release
   ```
   Output: `build/app/outputs/bundle/release/app-release.aab`.
4. Upload to an internal testing track in Play Console and enable Play App Signing.

## iOS (TestFlight)
Needs a Mac with Xcode and an Apple Developer account.
1. Open `ios/Runner.xcworkspace` in Xcode. Under Runner → Signing & Capabilities, pick your team. The bundle ID is `io.github.gauravpwagh.propcheck`.
2. Create the app in App Store Connect with the same bundle ID.
3. Build and upload:
   ```bash
   flutter build ipa --release
   ```
   Then upload `build/ios/ipa/*.ipa` with Transporter, or use Xcode → Product → Archive → Distribute App.
4. Add internal testers in TestFlight.
